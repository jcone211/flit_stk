- **日期**：2026-09-16
- **严重级别**：高（向用户输出了完整编造的技术分析，数值与真实行情偏差 30%~50%）
- **状态**：修复 1 + 修复 2 已实施（本文件）；修复 3 / 4 列为残余风险（见 §7）
- **关联证据**：`docs/debug.txt`（会话 `chat_mu2boev1pw8`）
- **关联代码**：`ai/ai.js`（guard 入口 / `hasPriorQuoteEvidence` / 新增 `topicNeedsKline`）、`ai/core/ai_guard.js`（`QUOTE_TOOLS` 维度拆分 / `hasQuoteEvidence` / `KLINE_TOPIC_RE`）

## 一、现象

2026-09-16 10:49:26 用户在同题会话里先问实时行情、接着问「用k线分析」，模型 **没有调用任何工具**（`docs/debug.txt` [041]→[042] 工具调用数 0）却输出了 1111 字的完整 K 线技术分析（[043]），其中价格、均线、涨跌幅、形态（涨停/跌停/双底）全部凭空编造。被用户当场识破：「你没实际调用工具」（[045]），才在 12 秒后真正调用 `read_stocks_kline` 取到真实数据（[049]）。

## 四、根因（代码级）

guard 入口 `ai/ai.js`（旧 435 行）：

```js
if (state.activeToolGroups.size > 0 && !quoteEvidence && !hasPriorQuoteEvidence()) { ... }
```

`hasPriorQuoteEvidence()`（旧 613-617 行）用 `QUOTE_TOOLS` 一把抓：

```js
// QUOTE_TOOLS 同时包含 get_stock_quote 与 read_stocks_kline（快照与 K 线不区分）
return state.chatMessages.some(m =>
    (m.kind === 'retained_data' && QUOTE_TOOLS.has(m.source))
    || (m.kind === 'tool_trace' && (m.calls || []).some(c => QUOTE_TOOLS.has(c.name) && c.ok === true)));
```

**链条**：10:48 的 `get_stock_quote` 成功 → 账本（tool_trace）留了 `get_stock_quote ok:true` → 10:49「用k线分析」这轮 `hasPriorQuoteEvidence()` 返回 **true** → 入口第三个条件不满足 → **guard 整块跳过** → 编造正文直接 `commitAssistant` 落地。

**本质**：guard 想验证的是「本轮正文的数值是否有真实来源」，实现成「历史上任何时刻取到过任何行情数据」就不拦。证据粒度缺了「数据维度」与「时效」两维——**实时报价 ≠ K 线历史**，二者不能互相充当证据。

> 同一漏洞的次要表现：[036]「分析这支股票」同样零调用被放行（那次是原文复刻、未翻车）；第一条会话 [023] 则展示了另一极——用户提供的卖出价 36.28 被模型复述，guard 误判「行情名词+价格数值」注入强制纠正，白跑一轮。**修复必须同时压低漏杀与误杀。**

## 五、修复方案（本次已实施）

### 修复 1：证据按「数据维度」（快照 / K 线）分类验证

- `ai/core/ai_guard.js`：
  - 新增 `SNAPSHOT_QUOTE_TOOLS`（`get_stock_quote` / `get_portfolio_quotes`）、`KLINE_QUOTE_TOOLS`（`read_stock_kline` / `read_stocks_kline`）；`QUOTE_TOOLS` 保持为全集（账本「行情成功」标签等语义不变）。
  - 新增纯函数 `hasQuoteEvidence(entries, klineNeeded)`：`klineNeeded=true` 时只认 K 线类工具的成功记录；`false` 时认全集。
  - 新增 `KLINE_TOPIC_RE`：`K线 / 日k线 / 日线 / 技术分析 / 均线 / MACD / KDJ / MA5 / MA10 / MA20 / 复盘 / K线图 / 蜡烛图`。**有意收窄**（不含「走势/形态/20日/30日」这类口语宽泛词），避免误触发强制取数。
- `ai/ai.js`：
  - `runAgentLoopBody` 增加 `quoteEvidenceKline`（K 线维度本轮证据）。
  - 新增 `topicNeedsKline(apiMessages)`（与 `quoteTopicNearby` 同口径扫描、回看 4 条用户消息）；guard 入口改按话题维度取证据：`curEvidence = klineNeeded ? quoteEvidenceKline : quoteEvidence`，历史证据用 `hasQuoteEvidence(state.chatMessages, klineNeeded)`。

### 修复 2：历史「同维度」证据存在时，`correct` 降级 `pass_warn`

本轮无匹配证据但历史确有同维度证据时，正文里的数值大概率是「复述早轮行情」（本就正确），若照旧走 `correct` 会打断体验（多等 6~12 秒 + 一次额外取数/免费额度）。因此入口只要 `!curEvidence` 就过 `decideQuoteGuard`，当 `prior === true && action === 'correct'` 时降级为 `pass_warn`：**正文照发，只补一行**「本轮没有重新取数，以下行情数值来自较早轮次的取数记录，如需最新数据请再问一次」。

### 修复后行为矩阵（activeToolGroups > 0 时）

| 场景 | 本轮成功取数 | 历史同维度证据 | 行为 |
|---|---|---|---|
| K线话题 + 本轮已调 read_stocks_kline 成功 | ✅ | — | 放行（guard 不判定） |
| K线话题 + 零调用 + 历史只有 get_stock_quote（**本次翻车点**） | ❌ | ❌（维度不匹配） | `correct` → 强制重新取数 |
| K线话题 + 零调用 + 历史有 K 线证据 | ❌ | ✅ | `pass_warn` 放行 + 一行时效提示 |
| 现价话题 + 零调用 + 历史有快照证据 | ❌ | ✅ | `pass_warn` 放行 + 一行时效提示 |
| 现价话题 + 零调用 + 无历史证据 | ❌ | ❌ | 原三态判定（correct/drop/note/pass） |
| 无行情信号正文 | — | — | pass（无打扰） |

## 六、体验影响评估（修复是否伤体验）

- **新增的代价只有两种**：① 跨维度提问（先实时后 K 线）多等一次取数往返 ≈ 6~12 秒（`read_stocks_kline` 实测 5939ms，`get_stock_quote` 5107ms），符合用户「问 K 线就要 K 线数据」的直觉；② 极少数「复述早轮行情」场景多一行底部灰字，不打断正文。
- **已避免的误杀**：「分析这支股票」（[036] 复刻正确行情表）不会因新判定被强制重取——`topicNeedsKline` 不命中该措辞，且同维度历史证据存在时已降级为提示。
- **guardRetried 闭锁保留**：无论修复与否，`correct` 最多注入一次，不会无限循环。

## 七、残余风险（本次未实施，列为后续项）

1. **形态词强信号（修复 3）未做**：`QUOTE_WORDS` 只含基础词（现价/收盘/跌停/涨停…），K 线阶段描述（缺口/双底/金叉/突破）目前只靠「行情名词+数字」负面命中，覆盖率有限。若要做，**必须加「本轮无任何取数成功」前置条件**，否则会误杀「用户提供数据、模型复述」场景（[023] 已是实例）。
2. **提示层措辞（修复 4）未做**：系统提示 `[强制取数]` 尚未明确「K 线/技术分析必须本轮调用日线取数工具」，模型行为仍依赖 guard 兜底。措辞务必保留「用户主动提供的数据（成交价/成本/股数）可直接复述，不算编造」的例外。
3. **guard 无法验证正文数值与工具返回是否一致**：即使本轮取了数，模型仍可能张冠李戴（A 股数据写进 B 股分析）。当前修复只解决「无证可查」，「有证乱用」仍需正文级校验或逐步提示。
